# 操作・情報・表現の確認

入力・UI・空間・動作・芝居・音が、狙う体験をプレイヤーへ届ける経路を扱う時に読む。代表的な行為を「情報を見つける→意図して操作する→状態が変わる→結果を受け取る→次へ進む」と追い、途切れる箇所に関係する節だけを使う。体験設計、試遊、採否、記録は [本体](../SKILL.md) の同じ改善ループへ戻す。

制作者の制作体制・画風・予算・作品固有の方針はゲーム側の文書と現在の依頼を確認する。本資料で特定の画風や制作方式を全作品の必須条件にしない。

## 意図した行為が届くか

入力やUIを変える時は、対象となる機器で必要な操作へ到達し、選択・決定・取消・復帰できるかを確認する。画面や詳細表示を閉じた後のフォーカス、再割当後の操作案内、長押し・同時入力・入力の競合など、今回の変更で影響する状態を選ぶ。マウスで動くことをコントローラーやタッチの証拠にしない。

反応が鈍い時は、入力の受付、状態による制限、処理・描画、見える応答を切り分ける。意図した溜めや硬直と、入力を受けたか分からない遅延を区別する。速度や演出を増やす前に、対象版と実行条件で原因を確かめる。時間や性能の基準はゲーム側から受け取り、共通の秒数を押し付けない。

## 判断に必要な情報が届くか

UIや予告を変える時は、今の状態、可能な行為、選択の結果に必要な情報を、実背景・実表示サイズで読み取れるか確認する。HUDが操作対象を隠していないか、文字拡大や対象言語・画面比で欠けないかなど、対応範囲に合う条件を選ぶ。

意図した難しさと、見えない・聞こえない・操作できないことを分ける。重要な情報が色や音だけに依存する箇所、持続入力の負担、強い動きが妨げになる箇所では、代替の手掛かり・操作・表示設定を検討する。設定があってもそこへ到達できなければ解決にならない。謎の答えを明示することと、手掛かりを受け取れることも分ける。

## 動きと芝居を組み立てる

- 新しい芝居やタイミングを探る時は、絵コンテと仮音・タイミング付き試作で注意の向きと間を比較する。既存場面の局所修正では、その場面を直接直して比較できれば作り直さない。
- 歩行は足の接地と移動速度を合わせる。受け渡しは物体の軌道・接触・保持・手放しをつなぐ。救助は支える姿勢の保持と双方の反応を成立させる。
- 接触を保ったまま相手が反応するなど、動作の重なりが必要な時は逐次再生だけに限定しない。必要な中間動作とタイミングを作り、静止ポーズの枚数や動作名の数を達成条件にしない。
- 行動、接触・効果、状態変化、相手の反応の時間関係を見せる。音の発生位置・時点を動作と合わせ、最終数値の一括更新だけで因果を消さない。

## 実画面で確かめる

実表示サイズ・実際の入力方式・等速・UI表示ありで、シルエット、遮蔽、接地、接触、視線、間、音の同期を確認する。アニマティクスは注意と間の比較に使い、操作可能な試作で入力への応答を確かめる。

素材や場面を量産する前に、代表場面で使えた素材・動作・タイミング・制作工程を既存資料へ残す。観測と未確認点は現在の課題の同じ記録へ加える。表現の成立は面白さや感動の証明ではなく、その判断は既存の試遊・採否に戻す。

新しい素材群や制作経路を使う時は、必要な状態、視点、相対寸法、透過・ピボット等の取込条件を制作担当と揃え、代表一点を実ゲームへ取り込んで確認する。背景・人物・UIが一緒に表示された時の役割の見分けや統一感も見る。画像や音声の生成成功だけでゲーム内の成立とせず、確認できた条件から展開する。既存素材の局所修正では影響範囲に絞る。

## 詳細が必要な時の一次資料

- [Xbox Accessibility Guidelines: Input](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/107)：入力方式、再割当、入力負荷。
- [Xbox Accessibility Guidelines: UI navigation](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/112)：移動・フォーカス・設定への到達。
- [Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/full-list/)：利用条件に応じた補助観点。全項目を毎回の工程や認証済みの合格判定にはしない。
