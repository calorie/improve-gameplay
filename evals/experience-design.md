# 体験設計を中心にした全体構成の見直し（2026-11-07）

## 目的と設計判断

入口は依頼範囲と判断責任、改善ループは仮説と採否、参照資料は必要な判断を具体化する知識を持つ。世界設定の専門設計、エンジン実装、素材制作の担当からは同じ課題へ成果物と確認結果を返す。制作管理や配信の全工程を本Skillへ集約しない。

今回の監査では、既存の単一ループ、限定依頼の尊重、正史の権限、観測と楽しさの区別を維持した。世界観だけの委譲を設計資料の案内より前に置き、代表場面の情報→行為→結果→次の期待を原因の切り分けに使う。各参照もこの判断へ戻る構成にした。

- design-depth：数値条件、反復後の蓄積、学習、資源の流れから設計案を検討する。
- scene-review：操作への到達、情報伝達、動作・芝居、素材取込を同じ体験の経路として確認する。
- evaluation：その原因を検証できる版・機器・状態・時間範囲の証拠を選ぶ。
- record-format：限定依頼の別作業枠と、元の全体記録との関係を明示する。

新しい必須GDD、全項目チェック、固定の性能・勝率・継続時間、別の評価台帳は追加していない。JSON形式とチェッカーも変更していない。

## 行動試験

現行版 fee816e を新しい文脈のエージェントへ渡し、次の4件について最初の対応・判断根拠・終了条件を回答させた。期待回答や改訂案は与えていない。各ケース1試行であり、実ゲームの操作はない。

| ケース | 現行版で観測した方針 |
| --- | --- |
| 携帯機の商店で詳細を閉じると操作不能、再割当後の案内も古い。店画面だけ修正 | 入力先と復帰、再割当表示を切り分け、実機で購入・往復を確認。範囲を保持 |
| 放置型の庭で翌日には買う物がなくなる。価格10倍・受取期限案を評価 | 翌日までの収支と選択肢を追い、義務感と楽しさを区別。実装へ広げない |
| エフェクト追加後の場面切替で手触り悪化。10分で速度調整を試したい | 現行版の入力反応・フレーム時間を先に測り、画風と予算を保持 |
| JSON必須、全体core未解決、今日の依頼はHP表示色だけ | 全体記録を保持し、明示範囲で別作業枠を選択。全体完成と混同しない |

4件とも概ね適切な方針だったため、知識が全面的に欠落しているという結論にはしない。改訂は必要な観点への到達と境界の明確化を狙う。詳細JSONでは全体枠でminorだけを選ぶとpriorityゲートが拒否することを別途確認した。これをゲート緩和で解消せず、既存の別作業枠へ正しく接続する。

改訂後は別の新しい文脈で7件を各1回確認した。上のUI・庭・性能の3件に加え、世界観だけ、ビルドだけ、沈黙が核の一場面提案、未取込の敵画像からの量産判断を用いた。専門への委譲、非適用、静かな作品の意図、代表素材の取込を含め、依頼範囲と未確認の扱いに重大な逸脱は見られなかった。回答者へ期待する答えは渡していない。ケース構成が異なり、対照群の反復比較でもないため、成功率や改善率を算出しない。

限定記録については架空のfixtureで、全体枠のminorだけを選ぶと拒否、新しい限定枠の初回は受理、異なるboundaryを `--previous` にすると拒否、同じ限定枠の次記録は受理、を確認した。元のcore問題はopenのまま保持した。これは形式と手順の整合であり、ゲーム変更や試遊の実績ではない。

既存Pythonテスト35件、同梱例2件、Skill形式、Markdownのローカル参照34件が成功した。別担当が全差分と接続する参照を読み、重大な矛盾・責務境界の破壊は報告しなかった。

## 限界

本文比較、手順選択、記録形式の検証は、実ゲームの品質や対象プレイヤーの楽しさを実証しない。自動選択の頻度、長期開発での安定性、消費トークンの改善率も未計測。既存の評価例と同様、具体的な失敗や利用結果から必要な部分だけ更新する。
