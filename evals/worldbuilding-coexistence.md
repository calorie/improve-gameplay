# Worldbuilding専門Skillとの併用ケース（2026-11-07）

## 目的

既存の改善ループ、評価、記録を増やさずに、improve-gameplay と世界観専門Skillを併用できるか確かめる。以下は期待動作とテスト設計であり、実際のAI試行・実ゲームの楽しさ向上を実証した結果ではない。

| Case | 依頼 | 期待する担当と振る舞い |
| --- | --- | --- |
| W1 | オープンワールドの王朝史と文化を深掘りしたい。実装不要 | 専門Skillに委譲。設定候補・因果・正史権限だけ確認。改善ループ・試遊・詳細JSONなし |
| W2 | 地理上の資源矛盾を探して | 専門Skillによる監査。確定と仮説を区別し、勝手に正史を書き換えない |
| G1 | 戦闘で回避の無敵時間を調整して | improve-gameplay単独。関連する入力・境界・前後確認。世界観文書を不必要に開かない |
| M1 | 遺跡探索が退屈。歴史の手掛かりを活かして改善して | improve-gameplayが一つの改善仮説を管理。専門Skillが因果と手掛かりを提案。試遊・採否・記録は1つ |
| M2 | 世界法則の変更が序章と戦闘に影響する | improve-gameplayが体験の改善と比較を管理。専門Skillが正史IDと変更影響を提示。ゲーム側の採用権限を守る |
| N1 | 世界観専門Skillが導入されていない環境で企画相談 | 従来のdesign-depthで対応。専用Skill導入を必須にしない |

## レビュー指標

- 適切な担当を選択しているか、未導入でも対応できるか。
- 同じ改善問題で仮説・試遊・記録が二重になっていないか。
- 世界設定を勝手に正史へ確定しないか。
- 世界観だけの相談をゲーム実装へ拡大しないか。
- 実装・テスト成功と、人間が面白いと感じた証拠を区別するか。

## 帰属上の注意

運用手順を整理したことだけでゲームが面白くなったとは判定しない。公開リポジトリの評価ケースには、非公開ゲームの仕様や試遊記録を転載しない。

現段階で、専門Skill併用時の実トークン消費、開発速度、人間の楽しさの向上は未検証。将来同一課題で「improveのみ」「worldbuildingのみ」「併用」を同じ予算・評価条件で比較する。
