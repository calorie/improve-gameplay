# 初版の検証記録 — 2026-11-01

これは架空の資料を使った手順と記録ゲートの検証。ゲームを実行した試遊や、人間の楽しさの実証ではない。

## 行動テスト

同じ戦術RPG資料を、履歴を渡さない別エージェントへ5回ずつ提示した。事前の評価基準は、核の問題の選択、過去版と現在版の区別、理解と楽しさの区別、直接の楽しさ確認、悪影響確認、終了と引き継ぎ。

| 観測 | スキルなし | スキルあり |
|---|---:|---:|
| 装飾より核の選択・結果の修正を優先 | 5/5 | 5/5 |
| AI完走や過去版の試遊を現在の楽しさの証拠にしない | 5/5 | 5/5 |
| 次の試遊で楽しさ・退屈さを直接確認する質問を明示 | 0/5 | 5/5 |
| 人間不在で楽しさ未検証を維持 | 5/5 | 5/5 |

スキルなしでも大半の重要な診断はできた。主な改善は、理解の確認だけで終わる抜けを減らしたこと。無指示の回答例には「何を予測し、なぜその手を選び、誰との関係がどう変わったか」、適用後には「楽しい／退屈な瞬間、続きを遊びたいかと理由、旧版との好み」が入った。

これは一つの資料に対する5回の小さな比較。統計的な優位性、他モデルへの一般化、作品の楽しさ向上を証明しない。評価者は作成者のため採点の独立性にも限界がある。

## 調整に使わなかった例

別の1エージェントが二つの例を確認した。

- 線形の会話作品：操作数や短文化を一律に加点せず、余韻と人物への関心を回復する案を選択。異なる初見集団の結果から単純な因果や優劣を断定しなかった。
- 救助の芝居が未制作の作品：ブルームと暗転短縮で完成にせず、接触・移動・反応を実現する制作手段の小試作を選択。未提供の参考映像を根拠にしなかった。

## プログラムと独立レビュー

Python標準ライブラリのunittestで35件を確認。対象は現在版と範囲の証拠、人間証拠、比較の両版、重大問題の優先、契約の保持、予算、停滞、履歴、JSON不正入力等。テストは実装前または不具合修正前に失敗を確認してから通した。

別のレビュー担当がコードと資料を読み、具体的な反例を提示した。修正済み：
- IDを残したまま問題内容を別件に置き換える抜けを塞いだ。
- 過去に解消した問題を毎ビルド再検証しないと継続できない問題を、resolved_buildの保持で修正した。
- 仮説を交互に切り替えると停滞を見逃す問題を修正した。
- 極端に大きな数値で異常終了する問題と、予算終了後にゼロ分作業を始められる問題を修正した。
- 追加の自己確認で、過去版の負の証拠を現在の不合格へ直接流用する問題も修正した。

## 再現

通常のコード確認：

```bash
python3 -m unittest discover -s <skill-dir>/tests -v
```

行動確認：新しい文脈へtactical-case.txtのみを渡す条件と、このスキル＋同じ資料を渡す条件を比較する。後者では資料の「他のスキル参照は不要」より明示指定した本スキルの利用を優先すると伝える。期待する回答や本記録は渡さない。回答の全文を読み、理解の質問を楽しさの質問として数えない。heldout-cases.txtは調整に用いた後は新しい保留例を追加する。
