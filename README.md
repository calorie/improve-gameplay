# improve-gameplay — ゲームの面白さを磨く

AIによるゲーム開発で、対象プレイヤーにとっての面白さを中心に改善を反復するための汎用スキルです。特定のゲーム、エンジン、ジャンルや既存の `game-development` プラグインには依存しません。

## 何をするか

- 世界観・ゲーム性・ストーリーを深掘りし、世界の規則、プレイヤーの行為、人物の動機と結果をつなぎます。
- ゲームが動くこと、理解できること、楽しいことを分けて評価します。
- 瞬間、一連のプレイ、対象全体で観察し、物語・遊び・UI・表現のつながりを確認します。
- 最重要の問題から原因仮説を選び、実装前後を比較します。コアが未成立のまま無関係な装飾へ進むことを抑えます。
- 作業予算、停滞、未解決問題、証拠を記録し、別のセッションでも再開できるようにします。

これは自動でゲームを操作するプログラムではありません。スキルを利用するAIと、その環境にあるエンジン・操作・録画等の道具が実行を担います。通常は「重要な問題を一つ選ぶ→変更→影響確認→採否」を短く回します。Pythonチェッカーは必要な節目で詳細記録を検証する補助で、面白さそのものを数値認定するものではありません。

## 一度インストールし、普段どおり依頼する

このリポジトリは単独のスキルです。入口は [SKILL.md](SKILL.md)。`agents/openai.yaml` の `allow_implicit_invocation: true` により、対応環境がゲーム開発の依頼から自動選択できます。毎回スキル名を指定したり、評価手順をプロンプトに書いたりする必要はありません。

ローカルのCodexでは、最初の一度だけ次のように依頼できます。

```text
$skill-installer を使って、https://github.com/calorie/improve-gameplay の
ルートにあるスキルを個人用としてインストールしてください。
```

ローカルで手動配置する場合は、このディレクトリ一式を `~/.agents/skills/improve-gameplay/` に置きます。同名スキルを既に管理している環境では、その既存のスキルを更新し、重複して配置しないでください。ChatGPT Workではスキルをインストール・有効化する機能を使います。個人用に有効化すれば、対象のゲームやセッションごとの設定追加は不要です。インストール方法と対応範囲は [OpenAIの公式ガイド](https://learn.chatgpt.com/docs/build-skills) を参照してください。

インストール後は、ゲームを読み取り・実行できる開発セッションで、例えば次のように依頼します。

```text
敵の予備動作を見て回避できるように調整して。
```

```text
救出後の会話を、直前の戦闘結果に自然につなげて。
```

```text
このゲームをもっと面白くして。今回は最大30分。
```

| 依頼 | AIの進め方 |
|---|---|
| 構想・世界観・人物・物語の深掘り | 確定設定と仮説を分け、有力案や因果を検討。設計相談では判断・未決定事項・検証案までに留める |
| 限定した機能追加・調整 | 狙う体験に結び付け、変更前後と関連場面を確認。既存メモか報告に短く残す |
| 全体改善・新規ゲーム・コアの修正 | 最重要の原因仮説を選び、実装・比較・採否を反復。短い現在状態と差分を残し、重要な変更・展開・完成の節目で全体を確認 |
| 明示された機械検証・必須工程・節目での厳密な照合 | 詳細な評価JSONとチェッカーを使う。通常の変更や引き継ぎのたびには新設しない |
| 分析・提案のみ | 根拠と改善案を回答。ファイルを作らず、実装へ進まない |
| 誤字だけ・ビルドだけ・ゲーム以外 | ゲーム評価の手順を追加しない |

初期設定や評価JSONの入力は利用者に求めず、AIが既存資料を読み、必要な記録を作成・更新します。人間の試遊では、楽しい・退屈な瞬間、続きを遊びたいか、その理由を確認します。AIの予測だけで「人間が楽しめた」とは判定しません。

暗黙の選択は利用環境の判断に依存し、毎ターンの呼び出しを保証するものではありません。確実に指定したい場面では `$improve-gameplay` 等の明示呼び出しも使えます。常駐監視は行わず、ゲームの実行手段は利用環境が提供するものを使います。別のアクティブなセッションやその作業領域は操作対象にしません。

## 世界観・ゲーム性・ストーリーを深掘りする

[設計の深掘り](references/design-depth.md) は、企画や世界・人物・物語と遊びの接続を検討する時に使います。Schellの多角的な設計検討を主軸に、MDAのルール・振る舞い・体験、Wolfの世界構築論、Jenkinsの物語空間を必要に応じて参照します。

既存の改善ループの「把握→選択」を補う資料であり、別の評価・試遊・記録の工程は作りません。通常の数値調整や局所修正には追加の必須工程を設けず、線形作品や世界観だけの相談も依頼範囲に合わせて扱います。参照手法の実績と、本スキル独自の統合手順の検証実績は区別します。

## 世界観専門Skillとの共存

歴史・文明・文化・地理・正史の専門Skillがある場合は、その領域の設計・整合性確認を任せます。**プレイヤー体験を改善する依頼**では本Skillが問題選択→実装→試遊→採否を統括し、専門Skillの提案は同じ仮説・証拠・作業記録へ統合します。**世界観だけの設計依頼**では専門Skillを優先し、ゲーム改修や試遊を自動で開始しません。

専門Skillがなくても、従来どおり [設計の深掘り](references/design-depth.md) を使えます。正史の決定は各ゲームのプロジェクトルールに従い、専門Skillの合格を「人間が面白いと感じた」証拠に換算しません。境界の期待動作は [併用ケース](evals/worldbuilding-coexistence.md) に整理しています。

専門Skillの具体例は、独立リポジトリで配布する [Open-world Worldbuilding Skills Kit](https://github.com/calorie/openworld-worldbuilding-skills) です。ゲーム作業では環境のSkill一覧からインストール済みの `openworld-worldbuilding` を選び、公開された実際の入口と同梱資料を読みます。開発checkoutや公開元の本文を導入版として代用しません。[導入手順](https://github.com/calorie/openworld-worldbuilding-skills/blob/40a9aa2eb857cca698b260d7184a5c896cf87db8/docs/game-installation.md) に沿って導入した配布版を管理し、同じ課題・正史版・記録先に専門所見を返します。導入は任意で、未導入なら未参照と明記し、本Skillの既存手順で依頼範囲内の作業を進めます。自動導入・更新や専門資料の複製は行いません。

## 読み込みと記録の負担を抑える

既存の会話・作業メモ・観測を再利用し、足りない情報だけを読みます。詳細な参照資料は必要な節だけを開きます。同じ版・影響のない範囲の検証や、同じ内容の定型報告を繰り返しません。

反復と引き継ぎでは現在版、最重要の問題、直近の観測、次の確認、残予算を短く保持します。過去の証拠と記録は参照先を残し、毎回全文を複製しません。既存JSONも消さず、必要な項目だけを作業メモへ引き継げます。人間の楽しさが未確認であること、未解決の重大問題、失敗した仮説は保持します。

品質・面白さの向上と消費トークンの改善率は、実ゲームの利用ログではまだ検証していません。

## 必要な節目での詳細記録の検証

Python 3と標準ライブラリを使います。リポジトリのルートで実行します。

```bash
# 説明用サンプルの確認
python3 scripts/check_cycle.py assets/iteration.example.json

# プロジェクト側に保存した記録の確認
python3 scripts/check_cycle.py /path/to/game/game-evaluation/iteration-002.json \
  --previous /path/to/game/game-evaluation/iteration-001.json

# チェッカーのテスト
python3 -m unittest discover -s tests -v

# 同梱の架空事例で引き継ぎ記録を確認
python3 scripts/check_cycle.py evals/iteration-002.json --previous evals/iteration-001.json
```

この検証は通常の作業の前提ではありません。明示された機械検証、既存工程の必須条件、または節目で厳密な照合が必要な場合に使います。初回の記録では `--previous` を省略します。終了コード0は記録の規則を満たすことを示し、ゲームの面白さや観測内容の真実性を保証しません。
